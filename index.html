NYC Subway Crowding & Delay Analysis

Conducted a large-scale analysis of NYC subway ridership and real-time transit data to investigate crowding and service reliability across the subway system. Using MTA ridership, GTFS schedule data, and real-time trip feeds, I developed a crowding index and delay estimation pipeline to identify congestion patterns, recurring bottlenecks, and relationships between demand and delays.

NYC Subway Crowding & Delay Analysis

Goal

  • Understand subway crowding and operational reliability
  • Compare demand patterns with delays

Dataset

  • MTA Subway Hourly Ridership
  • Static GTFS Data

Tools Used

Python Pandas SQL Matplotlib Seaborn Tableau

Process

  • Performed preliminary exploratory analysis on the ridership dataset, and represented on a dashboard created using Tableau

Crowding Measurement

  • Created a crowding index to measure station crowding:
    • \[ \text{Crowding Index} = \frac{\text{Ridership}} {\text{Scheduled Trips}} \]

Delay Estimation

  • Matched GTFS stop times with real-time subway feeds
  • Calculated arrival/departure delays
  • Filtered weekday trips from 6 AM-12 AM

Connecting Crowding & Delay

Key Findings

  1. High ridership does not necessarily imply the greatest crowding

    2. The crowding index revealed that some stations with lower ridership experienced greater congestion pressure due to lower service frequency.

  2. Delay severity varies significantly across subway lines

    3. Brown (J/Z) lines consistently experienced the highest delays, while several higher-ridership lines showed comparatively lower delays.

  3. Crowding and delays are not strongly linked systemwide

    4. Scatterplot analysis showed weak relationships between crowding and delays overall, though patterns varied by line group.

Steam Game Review Sentiment Analysis

Investigated linguistic characteristics of Steam game reviews through sentiment analysis, readability analysis, and machine learning classification to identify patterns in review structure, vocabulary complexity, and sentiment expression.

Steam Game Review Sentiment Analysis

Goals

  • Explore the relationships between different word characteristics and writing patterns to better understand sentiment.
  • Identify which machine learning model is best at classifying sentiment.

Dataset

  • Steam Reviews&Games Dataset

Tools Used

Python Numpy Pandas Matplotlib Tensorflow Scikit-learn Keras NLTK

Process

Exploratory Data Analysis

  • Cleaned dataset by performing dimension reduction, removing empty values, removing miscellaneous URLs and symbols, and normalizing and tokenizing reviews.
  • Performed feature engineering to create features such as character count, word count, average word length, stopwords count, and stopwords ratio.
  • Performed sentiment analysis on dataset by counting stopwords (using Collections library), generating sentiment scores of reviews (using VADER), and generating readability indices of reviews (using TextStat).
  • Conducted exploratory data analysis on dataset, and used Matplotlib to generate visualizations.
Questions asked:
  1. Do positive and negative reviews differ in textual length and verbosity?

    2. Positive reviews tend to have lower word and character counts while negative reviews have higher counts.

  2. Do positive and negative reviews exhibit distinguishable linguistic characteristics?

    3. Readability is a stronger factor for positive sentiment, while word count and non-stopword count are stronger factors for negative sentiment.

  3. Do longer reviews exhibit greater linguistic complexity?

    4. There is a negative relationship between word count and readability index. Shorter reviews tend to be more readable.

  4. Do more readable reviews tend to express more positive sentiment?

    5. There is no distinct relationship between readability and sentiment scores.

  5. What role do stopword and non-stopword distributions play in sentiment expression?

    6. Non-stopwords tend to have neutral or positive sentiment scores. There is no distinct pattern for stopwords.

Classification Using Machine Learning

  • Implemented three classical machine learning models (Logistic Regression, Support Vector Machine, Naive Bayes) and one deep learning model (LSTM) to compare performance.
  • Developed machine learning pipeline that applied TD-IDF to vectorize data, then feed it into the classification models.
  • Developed LSTM model with ReLU and sigmoid activation functions and binary cross-entropy loss function.
  • Visualized results through confusion matrices.

Key Findings

  • Negative reviews tend to be longer than positive reviews (higher word and character counts), and have slightly higher complexity than positive reviews.
  • Longer, detailed reviews tend to have lower readability
  • Classical machine learning models Logistic Regression and Linear SVM had the highest accuracies at 87% when classifying reviews by sentiment.

NYC Subway Route Optimization Using Dijkstra's Algorithm

Developed a graph-based Python application implementing Dijkstra's shortest path algorithm on the New York City subway network.

NYC Subway Route Optimization Using Dijkstra's Algorithm

Goal

  • Apply Dijkstra's algorithm to the NYC subway system to generate the most optimal path between two stations.

Tools Used

Python Plotly Networkx

Process

  • Manually collected station names using a map of the NYC subway, and collected the distances between two stations (in miles) using Google Maps. These were used to form the nodes and edges of the network. Distance in miles was used as the weight of each edge.
  • Formed the network graph within the program using the nodes and edges.
  • Applied Dijkstra's algorithm through a function that took the graph and starting node as input.
  • Visualized the shortest path on an interactive network graph created using Plotly and Networkx.

Results

  • Upon running the program, the user is prompted to provide a start station and a destination station. Then the program produces the shortest route between the two stations, including other stations that are on that path, as well as the total distance in miles.

Reinforcement Learning Algorithms for CliffWalking Environment

Implemented reinforcement learning algorithms in the OpenAI Gym CliffWalking environment to compare model-free and dynamic programming approaches.

Reinforcement Learning Algorithms for CliffWalking Environment

Goal

  • Explore how reinforcement learning agents learn optimal decision-making strategies through interaction with an environment and compare the behavior of different RL algorithms.

Tools Used

Python Numpy Matplotlib Seaborn

Process

  • Implemented model-based algorithm Value Iteration and model-free algorithms Sarsa and Q-Learning through Python functions that returned learned values and policies.
  • Visualized learned values and sums of rewards per episode for each algorithm using Matplotlib and Seaborn.

Results

  • Sarsa produced a safer path while Q-Learning produced the optimal shortest path, but Sarsa yielded more rewards.
  • Sarsa is more suitable when learning is prioritized, while Q-Learning is more suitable when performance is prioritized.
  • Model-based algorithms are best when a planned route is needed to complete a task. Model-free algorithms are best when end rewards hold more significance and exploration is encouraged.
